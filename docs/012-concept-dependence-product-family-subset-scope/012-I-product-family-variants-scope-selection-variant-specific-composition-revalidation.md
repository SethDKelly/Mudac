# Purpose

Select current MUDAC product-family scope from the coherent Concept subsets proven by Phase 012-H.

This subgroup answers a different question from dependence validity:

```text
dependence-valid
  != meaningful capability subset
  != adopted product variant
```

012-I decides which coherent contractions are actually part of current MUDAC product scope, which are ordinary lifecycle/configuration profiles inside the adopted product, which are coherent but deliberately out of scope, and which remain deferred future candidates requiring policy/composition changes before adoption.

It also checks whether the selected scope requires immediate Phase-011 synchronization repair.

# Decision summary

**PASS — current MUDAC scope is one primary full live-competition product variant, not a catalog of reduced editions.**

The adopted current variant is:

> **PF-01 — MUDAC Live Competition Judging & Official Outcome**

PF-01 keeps the complete eighteen-Concept capability envelope in product scope because the current mandate spans preparation, blinded live judging, operational coordination, authoritative/correctable evidence, official outcome formation, optional recognition, and controlled external representation/release.

This does **not** mean every Concept must have an active instance or action in every Competition.

A Competition may legitimately:

- confer no Award;
- generate no Export yet;
- remain official but unpublished;
- delay Publication;
- use electronic, paper, or mixed capture;
- pass through pre-closeout states before Outcome Declaration;
- have no correction/successor event in ordinary operation.

Those are configuration/lifecycle differences inside PF-01, not separate product variants.

No reduced Concept subset is adopted as a separate current edition, deployment, tier, or application.

# 1. Scope-selection principles

012-I applies the following rules.

## 1.1 Purpose before combinatorics

A coherent subset is adopted only when it still serves the current MUDAC mandate rather than merely satisfying graph closure.

The current purpose requires a product capable of turning independent human judgments into fair, explainable, correctable competition outcomes under live event conditions while preserving bias control, attribution, operational resilience, historical truth, and controlled externalization.

## 1.2 Capability support versus active use

A Concept may remain in product scope even when a particular Competition does not exercise it.

For example:

```text
Award capability is in scope
  != every Competition must confer an Award

Publication capability is in scope
  != every official result must be published

Export capability is in scope
  != every lifecycle state must have an Export
```

## 1.3 Lifecycle state is not a product variant

The following do not create separate product-family variants merely because some Concept has no current instance yet:

- pre-judging preparation;
- an Evaluation Occurrence before obligations are established;
- Scorecard Draft before authority;
- Event Completed before official closeout;
- official-but-not-yet-exported state;
- exported-but-not-published state;
- published versus withdrawn/superseded representation state.

## 1.4 Channel choice is not a Concept-subset variant

Electronic, paper, assisted capture, and mixed operation remain channel/continuity profiles over the same semantic product variant.

## 1.5 No commercial-tier inference

Phase 012 scope does not define free/pro/enterprise editions, pricing tiers, deployment sizes, service topology, or packaging.

# 2. Adopted current product variant — PF-01

## PF-01 — MUDAC Live Competition Judging & Official Outcome

PF-01 is the current supported product/application variant.

Its capability envelope includes all eighteen current Concepts:

```text
Competition
Division
Team
Panel
Evaluation Occurrence
Evaluation Obligation
Rubric
Scorecard
Award
Identity
Participation
Alias
Access
Versioning
Provenance
Outcome Declaration
Export
Publication
```

This reflects current product scope, not a claim that all Concepts are mandatory direct dependencies of Competition.

## 2.1 Competition / competitor context

PF-01 includes:

```text
Competition
Team
Division
Alias
```

because the current competition model includes configurable competitive grouping, current Rank is Division-scoped, and the current blinded Judge-facing identity policy uses Alias + Division.

A Competition with only one meaningful competitive cohort may configure one legitimate Division when that cohort is genuinely part of competition policy.

012-I does **not** authorize manufacturing a meaningless placeholder Division solely to satisfy implementation convenience.

A truly no-Division product contraction remains a separate deferred scope candidate below.

## 2.2 Actor / authority context

PF-01 includes:

```text
Identity
Participation
Access
```

because current purpose requires attributable human continuity, scoped Judge/Organizer authority, controlled disclosure, expiration/separation of authority, and technical-support boundaries.

Access is not a universal dependency edge from Identity/Participation, but it remains in current product scope because protected Judge/Organizer operations and disclosure control are baseline product obligations.

## 2.3 Evaluator organization

PF-01 includes Panel as the current reusable Judge-grouping capability.

Ad-hoc reassignment/substitution during live operation does not require removing Panel from the product variant. Panel membership, occurrence participation, Evaluation Obligation responsibility, and Scorecard evidence remain distinct.

## 2.4 Evaluation structure

PF-01 includes:

```text
Evaluation Occurrence
Evaluation Obligation
Rubric
Scorecard
```

because current product purpose explicitly requires:

- bounded historical judging context;
- visible remaining evaluator responsibility;
- declared evaluation basis;
- independent Judge-authored judgment;
- distinction between work completion and authority.

012-H proved that these Concepts are not universally co-dependent. 012-I nevertheless keeps all four in the adopted product because the current product mandate needs the capabilities they independently own.

## 2.5 Authoritative evaluation support

PF-01 includes:

```text
Versioning
Provenance
```

because the adopted product claims authoritative Rubric bases, authoritative Scorecard evidence, correction, current eligibility, source-faithful paper capture, and reconstructible historical truth.

Working/preparation states without Versioning/Provenance may exist during ordinary operation, but PF-01 is not a working-only/non-authoritative product.

## 2.6 Outcome authority

PF-01 includes Outcome Declaration because ordinary completed Competition scope includes explicit official result authority.

The adopted product therefore preserves:

```text
calculated != recognized != official
```

and ordinary closeout remains:

```text
Competition.finalize
+ OutcomeDeclaration.declare
```

A Competition may pass through Event Completed before closeout, but "not declared yet" is a lifecycle state, not a separate completed-product variant.

## 2.7 Recognition

PF-01 includes Award capability because organizer-defined recognition is in the current mandate.

However Award is **event-optional**:

```text
PF-01 supports Award
  != every Competition must define or confer one
```

Official outcome without Award is therefore an adopted configuration of PF-01, not a separate product edition.

## 2.8 External representation and release

PF-01 includes both Export and Publication because controlled external representation/release is a current purpose obligation.

Their use remains optional and explicitly separated:

```text
source authority
  != Export representation
  != Publication release
  != transport delivery
```

PF-01 therefore supports:

- no Export yet;
- Export prepared but not published;
- official-but-non-public state;
- public non-official material where policy permits;
- public official-result release;
- withdrawal/successor release after correction.

These are operating/release profiles inside PF-01.

# 3. Adopted operating and configuration profiles inside PF-01

The following are explicitly **in scope** without creating new Concept-subset products.

## 3.1 Award-optional official outcome

```text
official outcome
+ no Award required
```

This is supported because Outcome Declaration does not depend on Award and Awards are recognition rather than official-authority prerequisites.

## 3.2 Official but non-public

```text
current Outcome Declaration
+ no Publication
```

This is supported and important. Official authority does not imply public release.

## 3.3 Prepared representation without release

```text
Export exists
+ no Publication yet
```

This is supported for printing, review, preview, continuity material, ceremony preparation, or delayed release.

## 3.4 Public non-official representation

```text
Export + Publication
+ no Outcome Declaration required for the represented claim
```

This is supported when source authority, disclosure policy, representation purpose, and publishing authority permit the non-official material.

## 3.5 Public official-result release

```text
Outcome Declaration + Export + Publication
```

plus appropriate current source/disclosure/publishing authority remains in scope.

## 3.6 Exceptional or no-result official disposition

PF-01 may establish an official declaration whose accepted OutcomeBasis records an exceptional/no-result disposition when governing policy legitimately supports that result.

It does not fabricate normal Team ranking/evaluation evidence merely to force an ordinary ranked outcome.

## 3.7 Paper/electronic/mixed continuity

All remain in-scope channel profiles under the same Scorecard/Rubric/Occurrence/Obligation authority model.

# 4. Coherent contractions not adopted as separate current product variants

012-H proved several contractions coherent. 012-I deliberately does **not** promote them into current supported standalone variants.

## 4.1 Single-cohort/no-Division product contraction

**Status: coherent but not currently adopted.**

Reasons:

- current blinded Judge-facing representation names Alias + Division;
- current Rank is Division-scoped;
- PF-01 already covers a legitimate single cohort when competition policy actually defines one Division;
- adopting a truly no-Division variant now would create avoidable variant-specific policy/composition divergence.

Future adoption requires explicit generalization rather than placeholder Division invention.

## 4.2 No-Panel judging product contraction

**Status: coherent but not currently adopted as a separate product variant.**

PF-01 retains reusable evaluator grouping because live preparation/coordination is a baseline need.

Direct/ad-hoc evaluator changes may occur operationally without turning the entire product into a no-Panel variant.

## 4.3 Evaluation Occurrence-only product

**Status: coherent but out of current product scope as a standalone product.**

Historical occurrence capture without responsibility/judgment capability does not satisfy the current judging/outcome mandate.

## 4.4 Evaluation Obligation-only product

**Status: coherent but out of current product scope as a standalone product.**

Responsibility tracking is valuable but is not the current product purpose by itself.

## 4.5 Working Scorecard-only product

**Status: coherent only as a non-authoritative capability contraction; out of current product scope as a standalone product.**

PF-01 requires authoritative/correctable evidence, not merely draft judgment capture.

## 4.6 Judging-only completed product without Outcome Declaration

**Status: coherent at dependence level but out of current product scope as a completed variant.**

Current purpose P-06 and mandate explicitly include outcome formation and official declaration.

A Competition may temporarily be in judging/Event Completed state before closeout, but stopping there permanently is not the adopted completed-product contract.

## 4.7 Recognition-only final product

**Status: coherent but out of current product scope as a completed variant.**

Award without Outcome Declaration may exist before official closeout, but recognition is not a substitute for official result authority.

## 4.8 No-Alias judging

**Status: coherent under the direct graph but out of current scope for ordinary competitive judging.**

The current purpose and disclosure baseline require bias-aware Team treatment and blinded Judge-facing identity handling.

Adopting intentionally non-blinded judging would require an explicit purpose/policy decision, not merely a synchronization tweak.

## 4.9 Authoritative evaluation without Versioning/Provenance

**Status: invalid under current authority semantics, not a scope candidate.**

Working states may omit the support Concepts; authoritative Rubric/Scorecard claims may not.

## 4.10 No-Division rank-derived recognition

**Status: coherent future possibility but deferred / not adopted.**

Current Rank is Division-scoped. Adoption would require explicit Rank/Award policy and composition generalization.

# 6. Why PF-01 keeps all eighteen Concepts in product scope

The Phase-012 graph established that most Concepts are globally optional across the mathematical family.

Product scope is narrower than that mathematical family.

PF-01 keeps all eighteen because the current mandate explicitly includes the capabilities they own:

| Concept family | Current product reason |
| --- | --- |
| Competition / Team / Division | live competition and competitive grouping |
| Alias | bias-sensitive Judge-facing identity |
| Identity / Participation / Access | attribution, scoped authority, disclosure control |
| Panel | reusable evaluator preparation/grouping |
| Occurrence / Obligation | actual judging context and remaining responsibility |
| Rubric / Scorecard | evaluation basis and independent judgment |
| Versioning / Provenance | authoritative lineage, correction, source/history truth |
| Award | supported organizer-defined recognition |
| Outcome Declaration | explicit official result authority |
| Export / Publication | faithful representation and deliberate release |

This decision is not a claim that a product implementation must instantiate every owner continuously.

# 7. Variant-specific Phase-011 composition revalidation

## 7.1 Adopted PF-01

**Decision: no immediate Phase-011 reopening required.**

Phase 011 was intentionally reconciled around the full eighteen-Concept application family now selected as PF-01.

Its current synchronization owners already support the adopted distinctions:

- Identity continuity ≠ Participation authority ≠ Access permission;
- Panel membership ≠ occurrence participation ≠ obligation responsibility;
- Occurrence / Obligation / Scorecard remain independent owners while composing in ordinary judging;
- Versioning + Provenance support authoritative Rubric/Scorecard actions;
- Award is optional recognition rather than required official authority;
- ordinary closeout coordinates Competition Finalization + Outcome Declaration;
- official does not imply public;
- Export may exist without Publication;
- Publication requires explicit release authority;
- correction never silently republishes or manufactures authority;
- paper/electronic capture preserves semantic parity.

PF-01 therefore matches the composition surface Phase 011 already validated.

## 7.2 Award-optional official outcome

**No revalidation required.**

The current outcome synchronization already treats Award as optional recognition and allows closeout basis to include required/current Award decisions only where applicable.

## 7.3 Official-but-non-public and prepared-but-unreleased

**No revalidation required.**

The current external-representation/release synchronization explicitly supports:

```text
Outcome Declaration Current
  → optional Export
  → optional explicit Publication
```

without authority collapse.

## 7.4 Public non-official material

**No revalidation required at Concept composition level.**

Current Export/Publication composition is source-generic and purpose/audience-specific. Applicable disclosure/publishing policy remains required.

## 7.5 Exceptional/no-result declaration

**No immediate revalidation required.**

Current outcome composition requires an exact accepted reconstructible OutcomeBasis rather than one fixed evaluation-source bundle. Operational exception policy remains the governing source for exceptional disposition.

# 8. Deferred variant revalidation routes

These routes are recorded so future scope expansion does not mutate dependence merely to fit old composition.

## 8.1 Truly no-Division variant

If adopted later, revalidate at least:

- `policies/anonymity-disclosure.md` — Judge-facing Alias + Division contract;
- `mechanisms/rank.md` — Division-scoped Rank;
- occurrence/presentation synchronization where Division is part of presented context;
- outcome/Award synchronization for rank-derived recognition.

Do not create a fake Division solely to avoid this work.

## 8.2 No-Panel full judging variant

If adopted later, revalidate:

- evaluator-set establishment;
- occurrence preparation/begin semantics;
- obligation establishment;
- Organizer live-operations/readiness assumptions.

The natural Phase-011 owner is Evaluation Occurrence / Obligation composition, not Panel intrinsic semantics.

## 8.3 Evaluation contraction omitting Occurrence and/or Obligation

If adopted later, revalidate:

- `evaluation-occurrence-obligation.md`;
- `evaluation-basis-scorecard-authority.md`;
- outcome evidence-eligibility rules where current full-product composition assumes ordinary occurrence/obligation evidence context.

Do not add false dependence edges to avoid variant-specific composition.

## 8.4 Completed judging-only product

Future adoption would require more than a synchronization tweak because current project purpose explicitly includes official outcome formation.

Revisit:

- project purpose/mandate;
- Competition closeout scope;
- outcome/finalization synchronization;
- externalization claims tied to official state.

## 8.5 Intentionally non-blinded judging

Future adoption requires explicit purpose/policy reassessment of P-02/P-08 and anonymity/disclosure rules before composition changes are considered.

## 8.6 No-Division ranked recognition

Future adoption requires:

- Rank input/scope generalization;
- Ranking Readiness policy review;
- rank-derived Award composition review;
- downstream mapping of ranking context.

# 9. No false variant proliferation

012-I explicitly rejects treating each of the following as a separate product:

- Award used versus unused;
- Export generated versus absent;
- Publication delayed versus completed;
- paper versus electronic capture;
- current versus affected/superseded authority;
- Draft versus authoritative Scorecard;
- pre-closeout versus finalized lifecycle state;
- ordinary versus successor declaration;
- discretionary versus rank-derived Award selection.

Those are configuration, lifecycle, policy, or channel profiles owned inside PF-01.

The current scope can therefore be summarized as:

  └─ PF-01 Live Competition Judging & Official Outcome  [ADOPTED]

Coherent contractions remain design knowledge, but they are not current supported editions.
