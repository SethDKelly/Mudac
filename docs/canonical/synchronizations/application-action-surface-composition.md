# Purpose

Define the current MUDAC whole-application action surface and cross-family chaining rules after Phase 011-C through 011-H established family-level composition.

This contract is the current owner for:

- direct versus coordinated application action exposure;
- composition-only Concept participation;
- system-triggered conceptual reactions;
- intentionally unavailable generic controls;
- cross-family semantic chaining;
- automation authority limits;
- cycle and hidden-coordinator prevention;
- over-/under-synchronization closure;
- application-level synergy claims.

It does not replace the family synchronization owners. It composes and constrains them at whole-application scope.

# Governing rule

> **Automation may propagate knowledge/currentness and execute already-authorized bounded composition consequences; automation may not manufacture semantic authority.**

A synchronization never becomes a canonical state owner merely because several actions participate in one application behavior.

# Action classes

## Direct (`D`)

A Concept action may be exposed as a purpose-specific MUDAC business action under its own authority and guards.

## Coordinated (`C`)

A purposeful application action coordinates several Concept actions or required composition consequences while preserving each participant's ownership.

## Composition-only (`P`)

A Concept action participates through a purpose-specific application action and is not offered as a generic standalone control.

## System-triggered (`S`)

A bounded reaction may follow from already-authoritative facts without a second discretionary user decision, provided it does not invent semantic authority.

## Intentionally unavailable (`X`)

A generic action is withheld when exposing it would bypass purpose-specific composition, duplicate a derived mechanism, or leak implementation-shaped control.

`controlled` / `high-consequence` are governance qualifiers on `D` or `C`, not separate action classes.

# Derived mechanisms are not write authorities

Readiness, Coverage, Aggregate, Rank, Ranking Readiness and Finalization Readiness are derived facts/mechanisms.

MUDAC has no generic direct action that writes those results.

Likewise Reconciliation remains work/process context rather than an authority-owning state machine.

# Whole-application authority chain

The ordinary chain is:

```text
Identity
  → Participation
  → explicit operating context
  → Access guard
  → Competition preparation/readiness/lifecycle
  → Evaluation Occurrence
  → Evaluation Obligation
  → Scorecard
  → Versioning + Provenance + obligation satisfaction
  → eligible evidence
  → Coverage / Aggregate / Rank
  → optional Award
  → Competition Finalization + Outcome Declaration
  → optional Export
  → optional Publication
```

Every arrow means supplied facts or application composition, not ownership transfer.

Optional stages remain optional unless Phase 012 later establishes an inclusion dependence for a particular product family.

# Correction chain

```text
smallest semantic owner corrected/invalidated
  → actual dependents reevaluated
  → derived currentness recomputed
  → explicit Award correction only when required
  → Outcome Declaration identifyAffected when materially dependent
  → explicit successor declaration when reconciled
  → Export currentness reevaluated
  → explicit Publication leave/withdraw/successor decision
```

Downstream affectedness never automatically writes backward into its source.

# Legitimate system-triggered reactions

Current permitted conceptual reactions include:

- contextual `Access.check`;
- derived readiness/outcome/currentness recomputation;
- Ready-state blocking change → `Competition.returnToDraft`;
- Complete Live Event → completion of currently Active ordinary live Judge Participations;
- verified dependency change → Outcome Declaration `identifyAffected` when applicable;
- verified Export dependency change → `markAffected` or `markStale` where semantically warranted;
- supporting Provenance participation required by a coordinated authority/correction action.

A reaction must be derivable from established authority and explicit composition rules.

# Automation may not manufacture authority

No automatic upstream change may, by itself:

- author or finalize a Judge Scorecard;
- satisfy responsibility without qualifying finalized evidence;
- create successor Judge responsibility merely because evidence became unusable;
- rebind Scorecard structural identity;
- clone participants/obligations into a replacement occurrence;
- confer/revoke/reassign an Award;
- Finalize Competition;
- establish an initial Outcome Declaration;
- confirm a successor Outcome Declaration;
- generate a replacement Export merely because a source changed;
- publish, withdraw or supersede a Publication;
- restore Participation/Access after resume;
- expose generic Versioning/Provenance administration as domain authority.

# Chaining invariants

1. Panel membership is not occurrence participation.
2. Occurrence participation is not responsibility.
3. Responsibility is not Scorecard evidence.
4. Event completion is not obligation completion.
5. Occurrence completion is not obligation completion.
6. Scorecard Draft is not authority.
7. Versioning is not semantic authorship.
8. Provenance is not source/domain authority.
9. historical satisfaction is not current evidence eligibility.
10. Coverage exception is not Coverage satisfaction.
11. Aggregate existence is not Rank eligibility.
12. Rank is not Award authority.
13. calculated is not official.
14. official is not public.
15. Publication is not delivery.
16. source correction is not destructive historical rewrite.
17. affectedness is not automatic successor authority.
18. one Identity with several Participations never yields unioned capabilities.

# Cycle prevention

The current composition contains repeated lifecycle/history progressions but no semantic authority cycle.

- Ready → Draft → Ready requires fresh readiness and explicit lifecycle transitions.
- Event Completed → exceptional Resume restores no dependent authority automatically.
- Finalized → source correction → successor declaration does not roll Competition backward.
- Export Affected → validation → Current occurs only when unchanged SourceBasis/content remains valid.
- Publication successor chains advance release history without rewriting predecessors.

No hidden workflow/coordinator state is required to break a cycle.

# Over-synchronization prohibitions

MUDAC intentionally does not synchronize:

- activation into mass Participation activation;
- Panel membership into obligation identity;
- Prepared occurrence into obligation creation;
- occurrence completion into Scorecard Finalization;
- Rubric supersession into historical rebinding;
- evidence invalidation into automatic re-evaluation;
- Coverage exception into factual success;
- Aggregate into automatic ranking eligibility;
- Rank change into Award transfer;
- Competition Finalization into embedded declaration state;
- Outcome Declaration into automatic Export/Publication;
- Export generation into Publication;
- source correction into automatic withdraw/regenerate/republish;
- Publication state into transport success.

# Under-synchronization closure

The current family owners explicitly cover:

- Participation/context/Access seams;
- readiness/lifecycle seams;
- occurrence/responsibility establishment and adjustment;
- Scorecard authority/Versioning/Provenance/satisfaction;
- unusable evidence and successor-work semantics;
- factual Coverage versus governed exception;
- eligibility/Aggregate/Rank composition;
- Rank-derived Award selection basis;
- Competition Finalization + explicit Outcome Declaration;
- declaration affectedness/successor confirmation;
- Export source currency;
- explicit Publication release/successor history.

No material whole-application composition seam is currently orphaned.

# Semantic convergence without runtime prescription

Repeated semantic intent must not create duplicate authority.

Examples include one logical Scorecard per obligation, one evaluation weight across successor Scorecard Versions, one ordinary initial Outcome Declaration per closeout scope, and predecessor/successor Publication identity rather than retargeting.

This contract does not prescribe transactionality, queues, idempotency keys, retries, locks, workers or storage constraints.

# Accepted application synergies

Current MUDAC composition creates these additional application benefits:

1. multi-capacity people with context-isolated Access;
2. reusable Panel planning plus truthful actual occurrence/responsibility history;
3. independent Judge judgment with durable Versioning/Provenance and responsibility satisfaction;
4. paper/electronic continuity without a separate paper domain model;
5. correction that preserves attributable historical truth;
6. governed continuation under incomplete evidence without falsifying Coverage;
7. calculated ordering separated from Award recognition and official declaration;
8. official authority staged independently from public release;
9. corrected public outcomes with explicit successor declaration/export/publication history.

These synergies justify composition, not Concept merging.

# Rejected hidden coordinators

Do not introduce a generic:

- Workflow;
- Run;
- Case;
- Task;
- Reconciliation state machine;
- Finalization coordinator;
- Result/Outcome aggregate owner;
- Release manager;
- Automation/Cascade controller;
- Synchronization state.

Such implementation constructs may later exist as realization mechanisms, but none owns an independent current MUDAC user purpose or semantic authority under Concept Design.
