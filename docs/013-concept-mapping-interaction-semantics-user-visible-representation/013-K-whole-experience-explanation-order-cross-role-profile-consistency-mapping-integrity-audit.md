# 2. Whole-experience explanation order

The mapped experience has one semantic explanation grammar, although no screen or navigation sequence is mandated.

Where materially relevant, a protected or consequential interaction should let the person understand:

```text
1. current Competition / capacity / audience context
2. subject or resource being interpreted
3. current authoritative or working state
4. material disclosure / eligibility / readiness / currentness qualification
5. blocker, warning, exception or uncertainty affecting action
6. legitimate purpose-specific action, if any
7. consequence of that action
8. confirmed result and retained history
```

This is an **explanation order**, not a wizard.

Preserve globally:

```text
dependence order != navigation order
synchronization chain != mandatory wizard
explanation order != mandatory page sequence
```

A compact/mobile/accessibility representation may reorder or progressively disclose details, but must preserve enough of this semantic grammar before consequential commitment.

# 3. Context before authority interpretation

A material action must be interpreted in the correct current context.

```text
Identity
  + one current Competition-scoped Participation/capacity
  + target resource
  + purpose
  + current Access
  + owner-specific preconditions
  → legitimate action interpretation
```

Identity, route, session, role-mode, QR, device or technical privilege never substitutes for current Participation/Access or semantic authority.

This rule is consistent across Judge, Organizer, support and multi-capacity use.

# 4. Cross-role consistency

## Judge

Judge experience centers on independent evaluation responsibility and Judge-safe disclosure.

Judge context does not receive Organizer-sensitive visibility merely because the same Identity also has Organizer Participation.

Judge-facing competitor identity remains Alias + Division under blinded policy. Peer Scorecards/Notes, Aggregate, Coverage, Rank and standings remain unavailable during ordinary judging.

## Organizer

Organizer experience coordinates many source owners without becoming a catch-all domain owner.

Preparation, Live Operations, Reconciliation/Outcomes, Materials/Publication and History are work contexts, not lifecycle or authority states.

Organizer urgency/support privilege never transfers Judge authorship.

## Multi-capacity human

```text
Judge Participation capability
  + Organizer Participation capability
  != unioned super-role
```

Changing current capacity changes the supplied Access/disclosure context; it does not mutate either Participation or source authority.

# 5. Event-completion consistency repair

013-K identified one genuine mapping drift in `judge-onboarding.md`.

The earlier text implied:

```text
Event Completed
  → ordinary private-evaluation Access necessarily denied
```

That was too strong after 013-E/G established that Competition Event Completed may coexist with an Outstanding Evaluation Obligation and remaining Judge work when current policy and Access permit continuation.

The repaired whole-experience rule is:

```text
Event Completed
  → ordinary live-event entry/readiness context ends
  != universal hidden Access revocation

Outstanding obligation after Event Completed
  + current policy / Access permits continuation
  → same logical Judge work may continue
```

A later amendment/correction or other special historical action still uses its own narrow current authority rather than restoring general event-day capability.

This is a Phase-013 mapping correction only; no upstream Concept/synchronization change is required.

# 6. Cross-profile consistency

Audience/profile differences may legitimately change **what is disclosed**, never what the underlying authority means.

Representative profiles include:

```text
Judge-safe
Organizer-sensitive
Ceremony-safe
Public
internal history / audit
```

They are projections over the same authoritative sources, not parallel products or competing truth models.

Preserve:

```text
profile may omit protected information
profile may transform presentation faithfully
profile may qualify currentness/authority
profile may not invent source truth
profile may not promote source authority
profile may not erase retained history
```

Judge-safe Alias + Division, Organizer-sensitive administrative identity, and Public/Ceremony disclosure can therefore differ without changing Team/Alias/Identity history.

# 7. Source state, derived state and representation state remain distinct

Whole-experience consistency requires these layers never collapse:

```text
source authority
  != derived projection
  != official declaration
  != Export representation
  != Publication release
  != delivery observation
```

Examples:

```text
Outstanding obligation != Remaining Work as writable state
Coverage fact != exception disposition
Aggregate != rank eligibility
Rank != Award authority
Finalization Readiness != Competition Finalized
Competition Finalized != Outcome Declaration
Outcome Declaration != Export
Export currency != Publication state
Publication Published != delivery
```

No Experience owner introduces a generic status or workflow entity that owns these meanings collectively.

# 8. Current versus historical consistency

The accepted corpus uses the same temporal discipline:

```text
current != historical
superseded != invalidated != replaced != affected != stale
```

Historical state remains reconstructible without implying current authority.

Examples:

- historical Participation does not restore current Participation;
- past Panel membership does not rewrite occurrence participation;
- prior Scorecard Version remains history after successor authority;
- Satisfied obligation remains historically Satisfied even if evidence becomes ineligible;
- Affected Outcome Declaration remains the latest declared official authority until explicit successor confirmation;
- historical Export/Publication remains attributable after supersession/withdrawal.

# 9. Whole-application action traceability

Every material interaction must trace to the Phase-011 application action surface or to a non-authoritative read/projection/working/implementation interaction.

Current classes remain:

```text
D — direct application action
C — coordinated application action
P — composition-only participant
S — system-triggered conceptual reaction
X — intentionally unavailable generic action
```

No `P` or `X` action becomes a generic UI control for convenience.

No screen, work area, route, checklist, confirmation, status badge or recovery state creates a sixth action class.

# 10. Material interaction classification

Every material Experience interaction must be explainable as one or more of:

1. purpose-specific `D` or `C` application action;
2. current/historical source query/read under current Access/disclosure;
3. `P`/`S` consequence represented through its purpose-specific owner action or system reaction;
4. derived projection such as readiness, Remaining Work, Coverage, Aggregate, Rank or reconciliation condition;
5. non-authoritative working state such as Scorecard Draft/amendment Draft;
6. representation/currentness/release interaction owned by Export/Publication;
7. presentation-only state such as filtering, expansion, acknowledgement or local transport observation.

If a future interaction cannot be classified without inventing UI-owned domain state, it is a design defect or a trigger to reopen the natural semantic owner.

# 11. Action labels preserve owner meaning

The corpus consistently requires owner-specific language where consequence matters.

Examples include:

```text
Mark Competition Ready
Begin Evaluation Occurrence
Start Evaluation
Finalize Evaluation
Begin / Finalize Amendment
capture/transcription correction
invalidate evidence / occurrence
require successor evaluation
Complete Event
Confer Award
Finalize Competition & Declare Outcome
Confirm Successor Outcome Declaration
Generate Export
Publish Representation
Withdraw Publication
Publish Successor Representation
```

Generic `Done`, `Resolve`, `Fix`, `Force`, `Reset`, `Delete`, `Override` or `Submit` must not obscure materially distinct source/history consequences.

# 12. Availability and explanation consistency

An unavailable action should explain the semantic blocker when that can be done without leaking protected information.

Common categories are consistent across owners:

- wrong Competition/capacity context;
- denied Access;
- incompatible lifecycle;
- missing responsibility/source state;
- invalid/ineligible basis;
- incomplete Draft;
- blocking readiness/reconciliation condition;
- insufficient exception/correction/declaring/publishing authority;
- stale/affected/uncertain currentness;
- intentionally unavailable generic administration.

The same blocker category does not become a different authority merely because it appears in Judge versus Organizer or mobile versus desktop presentation.

# 13. Feedback and uncertainty consistency

Whole-experience feedback preserves:

```text
working persistence
  != semantic commitment

request dispatched
  != authority established

result unknown
  != confirmed success
  != confirmed failure
```

High-consequence actions require confirmed owner-specific postconditions before success is represented.

Retry/recovery reconciles current authority before repeating intent and converges on one legitimate semantic result.

# 14. Accessibility / degraded / paper consistency

013-J applies across every owner rather than creating an alternate action model.

```text
ordinary path semantics
  = accessible path semantics
  = responsive path semantics
  = degraded/recovery path semantics
  = paper/assisted path semantics
```

where the same operation is available.

Unavailable safely is preferable to a degraded path that bypasses Access, basis, confirmation or disclosure requirements.

# 17. Terminology integrity audit

Current Experience authority uses:

- `Evaluation Occurrence`, not `Judging Encounter`;
- `Evaluation Obligation`, not generic assignment/task;
- `Outcome Declaration`, not `Official Outcome Revision`;
- `Current | Affected | Superseded` for declaration currentness;
- `Current | Affected | Stale | Superseded | Retired` for Export currency;
- `Published | Withdrawn | Superseded` for Publication distribution state;
- subject-qualified `Complete`, `Finalized`, `Satisfied`, `Ready`, `Current`, `Published`, and `Resolved` meanings.

Historical terminology may remain in historical evidence, but current owners must not depend on it for current meaning.
