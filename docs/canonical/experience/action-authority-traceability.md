# Purpose

Keep the whole mapped MUDAC experience subordinate to the accepted Purpose, Concept, synchronization, dependence, policy and invariant model.

Screens, routes, work areas, buttons, dialogs, tables, status labels, previews, local state, recovery affordances and audience profiles may help people understand or invoke behavior. They do not independently own Competition truth, evaluation authorship, responsibility, correction, recognition, officiality, disclosure, release or history.

# Whole-experience explanation grammar

Where materially relevant, a consequential interaction should make the following semantic sequence understandable:

```text
current Competition / capacity / audience context
  → subject or resource
  → current authoritative or working state
  → material qualification / blocker / uncertainty
  → legitimate purpose-specific action
  → consequence
  → confirmed result and retained history
```

This is an explanation order, not a prescribed page flow.

```text
dependence order != navigation order
synchronization chain != mandatory wizard
explanation order != mandatory screen order
```

# Material interaction classification

Every material Experience interaction must be explainable as one or more of:

1. a purpose-specific direct (`D`) or coordinated (`C`) MUDAC application action;
2. a protected current/historical query or read under current Access/disclosure;
3. a composition-only (`P`) or system-triggered (`S`) consequence represented through its owning application behavior;
4. a derived projection such as Readiness, Remaining Work, Coverage, Aggregate, Rank or a reconciliation condition;
5. non-authoritative working state such as a Scorecard Draft or amendment Draft;
6. Export/Publication representation, currency or release behavior;
7. presentation/implementation-only state such as navigation, filtering, expansion, acknowledgement, focus or local transport observation.

If an interaction cannot be classified without inventing UI-owned domain state, it is a mapping defect or a trigger to reopen the natural semantic owner.

# Application action surface

The Phase-011 action classes remain authoritative:

```text
D — direct application action
C — coordinated application action
P — composition-only participant
S — system-triggered conceptual reaction
X — intentionally unavailable generic action
```

`P` and `X` never become generic controls for interface convenience.

A screen, work area, route, checklist, confirmation, status badge or recovery state does not create another action class.

# Context does not create authority

A visible or enabled control is not proof that the action is currently authorized.

Consequential execution remains grounded in current facts such as:

```text
Identity
+ one current Competition-scoped Participation / capacity
+ target resource
+ current Access
+ lifecycle / relationship / policy facts
+ action-specific preconditions
```

Route, role-mode, session, QR, device possession, technical administration or confirmation-dialog completion never substitutes for current semantic authority.

Likewise, a click/tap/request dispatch is not authoritative success. The owning action and synchronization must establish their postconditions.

# Work contexts organize attention, not lifecycle

Judge/Organizer modes and work contexts such as Preparation, Live Operations, Reconciliation/Outcomes, Materials/Publication and History are organizational views.

They do not create Competition lifecycle states or generic workflow authority.

Preserve:

```text
role/capacity mode != Participation authority
Preparation != Competition lifecycle state
Live Operations != Competition lifecycle state
Reconciliation != Competition lifecycle state / ticket owner
History view != restored current authority
```

# Cross-role consistency

Judge and Organizer contexts may expose different legitimate capabilities and disclosure, but they interpret the same underlying sources.

A single Identity holding both Judge and Organizer Participations does not yield a unioned super-role.

```text
Judge context
  → Judge Participation + Judge-safe disclosure

Organizer context
  → Organizer Participation + Organizer-sensitive disclosure

capability union
  → prohibited
```

Switching context selects another legitimate Participation; it does not mutate authority or source truth.

Technical/support capability is separate again and never manufactures Judge/Organizer semantic authority.

# Audience/profile consistency

Judge-safe, Organizer-sensitive, Ceremony-safe, Public and internal history/audit profiles may disclose different projections of the same underlying state.

A profile may omit or faithfully transform information, but it may not:

- invent source truth;
- promote source authority;
- erase retained history;
- convert possession into Access;
- convert officiality into Publication;
- convert Publication into delivery.

Actor visibility does not define audience disclosure.

# User-visible verbs preserve semantic ownership

High-consequence labels should identify the actual owner-specific action rather than flatten distinct semantics behind generic verbs.

Examples include:

- `Mark Competition Ready`;
- `Begin Evaluation Occurrence`;
- `Start Evaluation`;
- `Finalize Evaluation`;
- `Begin Amendment` / `Finalize Amendment`;
- capture/transcription correction;
- invalidate evidence or occurrence;
- require successor evaluation;
- `Complete Event`;
- confer/correct/revoke Award;
- `Finalize Competition & Declare Outcome`;
- `Confirm Successor Outcome Declaration`;
- `Generate Export`;
- `Publish Representation`;
- `Withdraw Publication`;
- `Publish Successor Representation`.

Generic labels such as `Resolve`, `Fix`, `Done`, `Close`, `Force`, `Reset`, `Delete`, `Override` or `Submit` must not obscure materially distinct authority/history consequences.

# Confirmation is intent evidence, not authority

Confirmation friction may show that a user deliberately requested a consequential action.

It does not satisfy domain preconditions or establish postconditions.

For example:

```text
confirm Finalize Evaluation
  != Finalization succeeded

confirm Competition closeout
  != Finalization Readiness bypassed

confirm Publish
  != disclosure/currentness prerequisites satisfied

confirm invalidation
  != correction authority granted
```

Unknown authoritative result remains unknown until reconciled or confirmed.

# Derived projections remain non-editable

Readiness, Remaining Work, Coverage, Aggregate, Rank, exception/reconciliation projections and similar explanatory states remain subordinate to authoritative sources.

Preserve:

```text
Remaining Work = projection over Outstanding obligations
Coverage factual state != exception disposition
Aggregate existence != rank eligibility
Rank != Award authority
Finalization Readiness != Competition Finalized
Acknowledged != source resolved
```

Remediation acts on the natural source owner or a specifically governed exception/correction action; it never manually writes the projection.

# Judge interaction traceability

Judge work is interpreted through:

```text
Identity / reverification
  → Competition-scoped Judge Participation
  → current Access / Judge-safe context
  → Evaluation Occurrence
  → Evaluation Obligation
  → one logical Scorecard Draft
  → explicit Finalize Evaluation
  → authoritative Scorecard Version + Provenance
  → obligation Satisfied
```

This chain explains authority; it is not a navigation wizard.

Panel membership is planning context, not occurrence participation, responsibility or evidence.

Navigation between Teams/work items never changes the judged subject implicitly. Alias + Division and exact Evaluation Basis remain sufficiently clear to prevent cross-subject or cross-basis judgment.

During ordinary judging, Judge context does not expose peer Scorecards/Notes, Aggregate, Coverage, Rank or standings.

## Event completion nuance

Competition Event Completed ends ordinary live-event operation but does not universally revoke all remaining Judge work by itself.

```text
Event Completed
  != all obligations terminal
  != all Scorecards Finalized
  != universal Access revocation
```

If an Outstanding obligation remains and current policy/Access permits continuation, the same logical evaluation may continue after Event Completed.

Later amendment/correction/history actions use their own narrow current authority; they do not restore a general event-day mode.

# Organizer interaction traceability

Organizer work coordinates independent sources without becoming a catch-all authority owner.

- **Preparation** acts on Competition, Team, Division, Alias, Participation, Panel, Rubric/evaluation basis and applicable policy; Competition Readiness remains derived.
- **Live Operations** coordinates actual occurrence/obligation state, current Judge work, participant adjustments, paper/correction paths, exceptions and `completeEvent`; urgency does not transfer Judge authorship.
- **Reconciliation/Outcomes** presents current eligible evidence and derived Coverage/Aggregate/Rank/readiness, then routes to owner-specific source, Award, closeout or correction actions.
- **Materials/Publication** uses Export generation/currentness followed by separate Publication authority.
- **History** preserves attributable predecessor/current/successor meaning without restoring current action authority.

# Current and historical interaction

Current and historical truth remain distinct across the whole experience.

Preserve:

```text
current != historical
superseded != invalidated != replaced != affected != stale
```

An interaction with historical state must make clear whether it is read-only inspection, amendment, capture correction, invalidation, replacement linkage, successor responsibility, successor Outcome Declaration, Export replacement/currentness work or Publication withdrawal/succession.

Historical presence alone never implies a current write path.

# Officiality, representation and release traceability

The externalization chain remains:

```text
source authority
  != Outcome Declaration officiality
  != Export representation/currentness
  != Publication release
  != delivery / recipient possession
```

More specifically:

```text
calculated != official
Outcome Declaration != Export
Export generation != Publication
Export currency != Publication state
Publication Published != delivery
recipient possession != current Access / release authority
```

A successor Outcome Declaration does not automatically create a successor Export or Publication.

# Uncertainty and recovery

When an authority-establishing result is unknown, the experience must expose uncertainty rather than offering a fresh intent as though failure were known.

```text
not attempted
in progress / pending
result unknown
confirmed success
confirmed rejection / failure
```

Recovery first reconciles current authoritative state, preserves newer authority over stale local state, and then offers the legitimate next action.

Retries, device changes, paper/electronic traces and reconnects converge on existing logical work rather than duplicate semantic effects.

# Accessibility and degraded parity

Accessible, responsive, keyboard, nonvisual, narrow-screen, assisted, paper and degraded paths preserve the same authority model.

```text
ordinary-path semantics
  = accessible-path semantics
  = responsive-path semantics
  = degraded/recovery-path semantics
  = paper/assisted-path semantics
```

where the same action is available.

If prerequisites cannot be established safely, the action may be unavailable. An alternate path must not weaken Access, authorship, disclosure, evidence weight, confirmation or historical rules.

# Mapping-integrity test

A mapped interaction is coherent when all of the following are true:

1. its current Competition/capacity/audience context is unambiguous where material;
2. its subject/resource is identifiable;
3. its state vocabulary is owner-qualified;
4. any derived value remains non-authoritative as appropriate;
5. the action maps to `D`, `C`, `P`, `S`, `X` semantics correctly;
6. current Access/disclosure is not inferred from navigation or possession;
7. success feedback corresponds to confirmed owner-specific postconditions;
8. current/historical lineage remains honest;
9. profile/accessibility/degraded representation does not change semantic authority;
10. downstream actions not made automatic by synchronization remain explicit.

Failure of one of these conditions is a mapping defect, not justification for UI-owned domain state.

# Design consequence

Downstream implementation should be able to trace every consequential interaction to the semantic owner and purpose-specific application action without treating route/component hierarchy or client state as domain structure.

No page, modal, wizard, status badge, work queue, task row, retry state or local client state becomes a MUDAC Concept merely because realization needs it.
