# External authority

MUDAC uses Daniel Jackson's Concept Design as its product-design methodology authority.

The MIT CSAIL Software Design Group describes concept design as organizing systems around independent concepts, their purposes, and the reactions that compose them, while keeping concept accounts focused on courses of action rather than implementation mechanisms.

# MUDAC adoption profile

MUDAC adopts the methodology principles needed to reason about:

- purpose-centered Concepts;
- independent Concept ownership;
- behavioral state/actions/operational principles;
- explicit composition/reactions;
- dependence and product-family reasoning;
- mapping into user-visible meaning;
- familiarity/reuse/genericity pressure;
- integrity under composition;
- scenario/misfit validation;
- final methodology-wide closure.

MUDAC's numbered phases are **not** claimed to be Daniel Jackson's official prescribed phase sequence.

The repository's [Base lifecycle operationalization](../canonical/governance/methodology-terminology.md) is a project/process control used to exercise the substantive methodology in dependency-safe order.

# Boundary

Concept Design governs product meaning.

OKF governs knowledge representation and progressive disclosure.

Architecture and implementation remain downstream realization layers.

A technology, UI pattern, database, module topology, framework, or historical implementation plan cannot establish Concept correctness merely because it already exists.
