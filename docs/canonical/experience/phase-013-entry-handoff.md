Provide the **current mapping-entry authority** prepared by Phase 012-J for the future Phase 013 — Concept Mapping, Interaction Semantics & User-Visible Representation.

# Current product variant entering mapping

The sole adopted current product variant is:

> **PF-01 — MUDAC Live Competition Judging & Official Outcome**

PF-01 includes the full eighteen-Concept capability envelope. Individual Competitions may legitimately leave particular capabilities unused or pass through lifecycle states in which no instance/action for a Concept exists.

Do not create mapping variants merely from:

- Award present/absent;
- Export present/absent;
- Publication pending/completed/withdrawn;
- paper/electronic/mixed capture;
- Draft versus authoritative Scorecard;
- Event Completed versus Finalized;
- current versus Affected/Superseded authority;
- ordinary versus successor Outcome Declaration;
- discretionary versus rank-derived Award selection.

These are PF-01 profiles/states, not separate products.

# Known mapping drift requiring Phase 013 attention

## Deprecated `Encounter` boundary

Several pre-existing Experience records still use `Encounter` as though it were the current evaluation work unit.

Current Concept ownership is:

```text
Evaluation Occurrence
  = bounded historical evaluation event / presented and actual participant context

Evaluation Obligation
  = one evaluator's responsibility for qualifying independent judgment
```

Phase 013 must decide how each current meaning is represented and explained. Do not perform a mechanical word replacement from `Encounter` to one of the two Concepts.

## Deprecated `Official Outcome Revision`

Some Experience material still says finalization establishes an `Official Outcome Revision`.

Current owner is:

```text
Outcome Declaration
```

which owns explicit declared official authority, Affected/currentness state and successor history.

## Historical synchronization routing

Older Experience material may link to the archival `concept-synchronizations.md` adapter.

Current composition authority is the seven-owner set listed in `canonical/synchronizations/index.md`, especially the whole-application action-surface owner for user-visible action mapping.

# Governing explanation-order rule

> **Expose enough upstream context, basis and authority for a downstream state/action to be interpreted correctly; never convert the dependence graph into a mandatory screen, route, navigation or wizard order.**

# Explanation obligations entering Phase 013

## Context / scope

Where ambiguity would change meaning, make enough of the following understandable:

```text
Competition
actor / Participation context
Team subject
applicable Division / Alias disclosure context
```

## Evaluation work

Before authoritative judgment commitment, the Judge must be able to understand the relevant:

```text
Evaluation Occurrence context
Evaluation Obligation responsibility where applicable
Rubric / Evaluation Basis
Judge-facing Team context
```

## Working versus authoritative evaluation

Preserve:

```text
Draft / preserved work
  != authoritative Scorecard evidence
```

and expose Version/Provenance meaning where currentness/authorship/correction matters.

## Evidence / derivation

Preserve:

```text
eligible authoritative evidence
  → Coverage / Aggregate
  → rank eligibility / Rank
```

without turning derived state into editable source truth.

## Recognition / official authority

Preserve:

```text
calculated != recognized != official
```

so Rank, Award and Outcome Declaration are not represented as one status.

## Externalization

Preserve:

```text
source authority/currentness
  != Export representation/currentness
  != Publication release state
  != transport/delivery realization
```

## Temporal/correction semantics

Mappings must distinguish current, historical, invalidated, superseded, affected/stale, replacement and successor meanings when those distinctions affect decisions or available actions.

# Application-action surface rule

Phase 013 maps the **application action surface established in Phase 011**, not an arbitrary union of Concept actions.

Current action classes remain:

```text
D — direct application action
C — coordinated application action
P — composition-only participant
S — system-triggered conceptual reaction
X — intentionally unavailable generic application action
```

A mapping must not expose `P` or `X` behavior as a generic user action merely because the underlying Concept has an intrinsic action.

# Actor and affected-party perspectives

Phase 013 planning must cover, where relevant:

- Judge;

- technical administrator/support operator;
- Student Team as materially affected party;
- external recipient of deliberately released material.

Do not assume one generic user perspective.
